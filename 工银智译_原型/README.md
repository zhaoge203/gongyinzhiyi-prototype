# 工银智译 · 原型系统说明

本目录为参赛策划案《工银智译——金融产品资料概要智能解读平台》的配套可运行原型。
原型的全部指标与结论均可由本目录代码复现。

---

## 一、目录结构

```
工银智译_原型/
├── data/                      输入：4 份真实产品资料概要（官方 PDF）
├── engine/                    引擎源码
│   ├── chain1_parse.py          链一 文档解析与语义分块
│   ├── chain2_extract.py        链二 要素结构化抽取 + 正则交叉校验
│   ├── chain3_interpret.py      链三 分层解读生成 + 认知确认题 + 锚点/表达校验
│   ├── chain4_compare.py        链四 同类产品对照 + 链五 质量评测
│   ├── chain6_graph.py          链六 LangGraph 状态机（含真实 human-in-the-loop）
│   ├── fidelity.py              保真度与可读性度量的唯一定义（共享）
│   ├── probe_fidelity2.py       保真度指标检出能力探针
│   └── run_all.py               一键跑通全部链条
├── ui/
│   ├── prototype.html           可点交互原型（浏览器直接打开）
│   ├── render_ui.py             界面稿渲染脚本（PIL）
│   └── ui_*.png                 4 张界面稿
└── engine/out_0*.json           8 份结构化产出物
```

---

## 二、运行方式

```bash
# 依赖：langchain-core, langchain-deepseek, langgraph, pypdf, pydantic
# 大模型：DeepSeek（需在环境变量 DEEPSEEK_API_KEY 中配置密钥）

cd engine
python run_all.py             # 一键跑通全部链条（约 3–6 分钟）

# 或分步执行
python chain1_parse.py        # -> out_01_parsed.json
python chain2_extract.py      # -> out_02_facts.json
python chain3_interpret.py    # -> out_03_interpretation.json
python chain4_compare.py      # -> out_04_comparison.json / out_05_metrics.json
python chain6_graph.py        # -> out_06_trace.json / out_07_human_review.json
python probe_fidelity2.py     # 指标检出能力探针

cd ui
python render_ui.py           # 渲染 4 张界面稿
python build_prototype.py     # 生成可点原型 prototype.html
```

> 环境说明：`engine/*.py` 使用 **Python 3.12**（langchain / langgraph）；
> `ui/render_ui.py`、`ui/build_prototype.py` 需 **Python 3.9**（依赖随附的 Pillow）。
> 可点原型 `prototype.html` 为单文件、无外部依赖，双击即可打开。

## 四、实测结果（四只真实产品，全部由程序自动核验）

| 指标 | 结果 |
|---|---|
| 原文锚点有效率 | **100.0%**（54 个受检项） |
| 表达合规率 | **100.0%**（54 个受检项） |
| 认知确认题格式与锚点校验 | **4/4 通过**（每只产品 3 道题） |
| 标签-数值归属一致率 | **100.0%**（16 个配对全部落地） |
| **原文完全不支持的数值** | **0 个** |
| 可读性门禁 | **4/4 通过** |
| 平均句长 | 原文 22.3–24.4 字 → 解读 17.3–27.4 字 |
| 综合费率对照 | 0.40% – 1.41%，相差 **3.52 倍** |
| 人工复核 interrupt | **两条裁决路径（approved / rejected）均验证通过** |

### 指标口径说明（重要）

- **锚点有效率**：解读的每条结论所标注的原文块 ID 是否真实存在。这是弱校验，只证明"指得着"。
- **归属一致率**：解读中的「标签-数值」配对（如"管理费 1.2%"）能否在锚点所在章节的正确标签下落地。
- **原文完全不支持的数值**：全文任何位置都找不到依据的数字。**本批次为 0**，这是最硬的一条结论。
- **已知边界**：归属一致率采用章节级窗口以避免误报（产品资料概要中申购费与运作费用本就分处不同小节），
  代价是无法检出同一章节内部的局部归属对调。精确检出需还原 PDF 表格行列结构，列为下一阶段改进项。

## 五、实测中发现并修复的问题（真实运行记录）

### 1. PDF 表格压平导致数值锚点丢失
「基金运作综合费率（年化）」与数值「0.45%」被拆成不相邻两行，数值一度被当噪声丢弃。
**修复**：禁止按行短过滤；对相邻块做标签—数值邻近合并。

### 2. 合规红线误拦正确的风险提示（累计三次误拦）
- 「本基金**不保本**」命中禁用词「保本」→ 加入否定语境识别（不/非/无/未 前缀不拦截）
- 「持有满**一定**时间」中的「一定」是形容词（意为"某个不确定的"）→ 加入词性判断，
  仅当后接「会/能/要/将/是/可以」时才判为绝对化表述
- 认知确认题必然要问「是否保证收益」→ 表达词表检查不适用于考题，改为只校验题目的锚点与格式

**结论**：中文合规词表审查必须处理词义与语境，不能只做字符串匹配；
"AI 初筛 + 人工复核"是这类系统能否上线的必要条件。

### 3. 结构化输出失败触发回退重写
模型多次把列表字段返回为 JSON 字符串或竖线拼接串（锚点、选项、答案均出现过）。
**修复**：放宽锚点分隔符集合（含 `|`）；选项字段预归一化；保留重试与回退路径。
实测中该路径被真实触发并生效。

### 4. 解读句长反而变长，被可读性门禁拦下
早期 R1 解读平均句长 69.6 字 > 原文 27.1 字（把难词换成长句，并未降低难度）。
**修复**：提示词增加"单句不超过 35 字"硬约束 + 确定性长句拆分后处理（只断句、不改字）。

### 5. 保真度指标自身存在盲区 —— 被自测推翻并重建（最重要的发现）
原实现为「解读中的百分比是否在原文任意位置出现过」。
用 6 个人工构造的语义错配样本测试（托管费说成管理费、申购费说成赎回费、
「60%–95%」说成「5%–95%」、年化说成月费率等），**6 个样本全部拿到 100%**。
原因：这些错误里数值都真实存在，错的只是挂在了哪个标签下。

**修复**：把指标升级为「标签-数值配对的上下文一致性」。
**方法论教训**：一个指标如果没有被故意用来检验"它能不能发现错误"，那它就没有被验证过。

### 6. 可读性门禁未接回生成链 + 两处口径不一致
门禁最初只存在于评测脚本，超标的解读照旧放行；且校验节点与评测脚本使用不同的
文本构成与阈值定义，导致同一只产品出现"校验通过"而"评测未通过"的矛盾结论。
**修复**：在 `fidelity.py` 中定义唯一的可读性与保真度实现，校验节点与评测脚本共用。

## 六、已知限制（如实说明）

- 使用通用对话模型，非行内已备案金融大模型。
- 检索增强以确定性检索实现（可审计性强、语义召回弱于向量方案），
  生产阶段应以向量检索为主、确定性检索为辅。
- 评测集规模为 4 只产品、且全部来自同一管理人同一模板，跨管理人稳健性未验证。
- 归属一致率指标无法检出小节内部的局部归属对调（需表格结构还原）。
- 原型未接入行内系统，**未做真实用户理解度测试**——"投资者是否更懂"这一核心主张
  目前没有实证数据支撑，只完成了"没讲错"的验证。
- 未做成本测算（单次解读 token 成本、全量产品月更新成本）。
